# Contributing

Thanks for helping improve Jerkgram.

## Before the first Stable public source snapshot

Until the first Stable source tree is published, the most useful contributions are:

- reproducible bug reports;
- documentation corrections;
- localization feedback;
- release/source transparency review;
- UI/runtime feedback from beta builds.

## Bug reports

Please include when possible:

- Jerkgram version or build number;
- iOS version;
- device model;
- exact reproduction steps;
- expected behavior;
- actual behavior;
- screenshots or a short recording when they materially help.

Do not include private messages, credentials or other sensitive user data unless you have removed or redacted it safely.

## Pull requests

Once the first Stable source snapshot exists, code contributions can be reviewed against a concrete public tree. Keep changes focused, explain the behavior they change, and avoid unrelated refactors in the same pull request.

## Project principles

- evidence over guesswork;
- focused changes over broad speculative rewrites;
- release source must correspond to real released code;
- privacy and user data deserve conservative handling.
